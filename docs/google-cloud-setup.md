# Google sign-in: Google Cloud and Supabase setup

What an app on `forge_core` needs before `signInWithGoogle()` works on a
device. Once per app; the values are public (they ship in the app) but are
passed as `--dart-define`s, never committed (see the README).

## Google Cloud

1. **One Web OAuth client.** Its client ID is both the Supabase Google
   provider's client ID and the app's `FORGE_GOOGLE_WEB_CLIENT_ID`
   (`serverClientId` for the plugin: the ID token's audience). Add the
   Supabase callback, `https://<project-ref>.supabase.co/auth/v1/callback`,
   as an authorised redirect URI. The client secret goes only into the
   Supabase provider settings.
2. **One Android OAuth client per signing certificate**, each with the
   package name and one SHA-1:
   - the **Play app-signing** key (Play Console → Test and release → App
     integrity → "App signing key certificate"), the one testers' installs
     carry;
   - the **upload** key (the release keystore; Play Console shows it too);
   - the **debug** key of every development machine
     (`keytool -list -v -keystore ~/.android/debug.keystore -alias
     androiddebugkey -storepass android`).

   A build signed with a key that has no client cannot sign in; CI's
   keystore-less `-debugsigned` builds use a throwaway key and never can.
   Android clients have no secret and nothing in the app or Supabase refers
   to them: Credential Manager matches the installed app by package and
   signature on Google's side.
3. **Consent screen** (Google Auth Platform → Audience): app name as on the
   store listing, support email, developer contact, homepage, privacy policy
   URL, the site as an authorised domain. No logo until the brand
   verification review is wanted. It starts in **Testing**: only listed test
   users (max 100) can sign in. Add the developers' accounts now; flip to
   **In production** before any build reaches testers outside the list (basic
   scopes need no verification review). The Play reviewer account must be a
   test user until then.

Nothing else: native Sign in with Google through Credential Manager needs no
API enabled.

## Supabase

- Authentication → Providers → Google: on, with the Web client ID and
  secret. Add the Web client ID to "Authorized Client IDs" if the dashboard
  shows the field (the ID token's audience must be listed).
- Leave "Skip nonce check" off: `PluginGoogleIdTokenSource` sends one nonce
  per process (SHA-256 to Google, the raw value to Supabase).
- Authentication → URL configuration: add the app's mail redirect to the
  allow list: its App Link (`https://<site>/apps/<app>/auth/`, preferred)
  or the custom scheme `<applicationId>://auth-callback` (with any
  underscore in the id dropped: a scheme cannot contain one). See
  `email-setup.md`. Google does not use it, but the email flows (FC-5) do.

## Behaviour notes

- **Nonce policy.** `google_sign_in` 7 is initialize-once and takes the nonce
  at `initialize`, so there is exactly one per process, generated by the
  package. Supabase verifies it on every exchange.
- **No second consent prompt.** The plugin separates authentication (the
  ID token, from `authenticate()`) from authorization (access tokens, from
  `authorizationClient.authorizeScopes`, which can prompt again). `forge_core`
  never asks for an access token; Supabase accepts the ID token alone.
- **"No Google account on this device"** arrives from the Android plugin as
  `unknownError` with a "No credential available" description; it is mapped
  to `ForgeAuthError.noGoogleAccount` so the UI can say so.
- **Sign-out** also calls the plugin's `signOut()`, so the next attempt shows
  the account picker again rather than silently reusing the last account.
